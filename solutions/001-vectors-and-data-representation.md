## A. 数据表示

### A1. 设计特征向量

一种合理表示是：

\[
\mathbf{x}=
\begin{bmatrix}
3.2\\
8\\
1\\
18
\end{bmatrix}
\in\mathbb{R}^{4}
\]

特征契约：

| 位置 | 名称 | 类型 | 单位或取值 |
|---:|---|---|---|
| 1 | 配送距离 | 浮点数 | 千米 |
| 2 | 待处理订单数 | 非负整数 | 单 |
| 3 | 是否下雨 | 二元数值 | `0` 否，`1` 是 |
| 4 | 骑手平均速度 | 浮点数 | 千米/小时 |

“是否下雨”可以编码为 `0/1`。如果线上把第 2、3 个特征交换，向量形状仍是 `(4,)`，程序可能不会报错，但模型会把“是否下雨”当成订单数、把订单数当成下雨标记。这属于**语义正确性错误**，单纯的 Shape 校验无法发现。

### A2. 判断能否直接组合

不能直接计算有业务意义的距离。两个向量虽然字段名称看起来相同，但价格和重量使用了不同单位。

至少还要检查：

- 特征名称和顺序；
- 数据类型；
- 计量单位和换算规则；
- 合法范围；
- 缺失值规则；
- 货币汇率采用的时间和来源；
- 特征缩放或标准化规则；
- 数据版本。

先统一美元/人民币、克/千克，再根据任务决定是否标准化。

## B. 手工计算

给定：

\[
\mathbf{x}=
\begin{bmatrix}2\\-1\\3\end{bmatrix},\qquad
\mathbf{y}=
\begin{bmatrix}4\\2\\-2\end{bmatrix}
\]

### B1. 基础运算

\[
\mathbf{x}+\mathbf{y}
=
\begin{bmatrix}6\\1\\1\end{bmatrix}
\]

\[
\mathbf{x}-\mathbf{y}
=
\begin{bmatrix}-2\\-3\\5\end{bmatrix}
\]

\[
3\mathbf{x}
=
\begin{bmatrix}6\\-3\\9\end{bmatrix}
\]

\[
\mathbf{x}^{T}\mathbf{y}
=2\times4+(-1)\times2+3\times(-2)
=8-2-6=0
\]

\[
\|\mathbf{x}\|_1=|2|+|-1|+|3|=6
\]

\[
\|\mathbf{x}\|_2
=\sqrt{2^2+(-1)^2+3^2}
=\sqrt{14}
\]

点积为 0，因此这两个非零向量正交。

### B2. 线性得分

\[
z
=5\times0.4+2\times(-0.5)+1\times2.0-0.3
=2-1+2-0.3
=2.7
\]

各部分贡献：

| 部分 | 贡献 |
|---|---:|
| 第 1 个特征 | `2.0` |
| 第 2 个特征 | `-1.0` |
| 第 3 个特征 | `2.0` |
| 偏置 | `-0.3` |
| 合计 | `2.7` |

### B3. Shape 推理

| 表达式 | 结果 |
|---|---|
| `(4,) + (4,)` | `(4,)` |
| `(4,) @ (4,)` | 标量，NumPy Shape 为 `()` |
| `(32,4) @ (4,)` | `(32,)` |
| `(32,4) @ (4,3)` | `(32,3)` |
| `(4,) + (3,)` | 不合法，维度不同且不能广播 |
| `(4,1) @ (1,4)` | `(4,4)`，外积形式 |
| `(1,4) @ (4,1)` | `(1,1)`，二维内积形式 |

判断矩阵乘法时，先检查内部维度，再保留外部维度。

## C. 概念解释

### 1. 向量为什么不只是一组数字

向量中的每个位置都有固定语义、顺序和单位。数值相同但特征契约不同的两个向量，表示的是不同对象，不能直接互换。

### 2. 点积为什么是加权求和

点积把每个特征 `x_j` 与对应权重 `w_j` 相乘，再把所有贡献相加。权重决定该特征对最终标量分数的方向和强度。

### 3. 数据视角与几何视角

数据视角把分量解释为业务特征；几何视角把向量解释为空间中的点或方向。前者保证语义正确，后者帮助理解距离、夹角、投影和分类边界。

### 4. Shape 正确为什么仍会预测错误

Shape 只验证分量数量，不验证名称、顺序、单位、预处理版本和缺失值语义。特征错位或单位漂移时，程序仍可正常运行。

### 5. 为什么大尺度特征会支配距离

欧氏距离会对每个维度的差值平方后相加。数值范围大的维度通常产生远大于其他维度的平方差，从而主导结果。

### 6. 三种 NumPy Shape 的区别

`(d,)` 是一维数组；`(1,d)` 是显式行矩阵；`(d,1)` 是显式列矩阵。它们参与矩阵乘法和广播时的规则与结果 Shape 不同。

## D. 错误诊断

### D1. 特征错位

1. 三个字段仍组成长度为 3 的数值数组，因此普通维度检查不会失败。
2. 应通过命名 Schema、统一特征转换代码、版本化数据契约、线上线下一致性测试和入口校验共同预防。
3. 数组长度只说明“有三个数”，无法说明三个数分别是什么。

更可靠的做法是先用带名称的结构接收数据，再由唯一的转换函数按固定顺序生成向量。

### D2. 广播问题

`prediction` 为 `(5,1)`，`target` 为 `(5,)`。NumPy 对齐尾部维度后，可能把两者广播成 `(5,5)`。

两种正确方式：

```python
prediction = prediction.reshape(-1)
assert prediction.shape == target.shape == (5,)
error = prediction - target
```

或：

```python
prediction = prediction.reshape(-1, 1)
target = target.reshape(-1, 1)
assert prediction.shape == target.shape == (5, 1)
error = prediction - target
```

关键不是选择哪一种，而是在整个实现中保持一致，并在计算损失前断言形状。

### D3. 单位漂移

1. 点积、距离、范数、归一化、模型预测和梯度都会受到影响。
2. 米和千米都是合法数字，Shape 和类型均不变，所以通常不会立即报错。
3. 应在 Schema 中声明单位，由共享转换函数完成换算，并增加固定样本测试、范围监控和数据版本校验。
